\section{Prompt template (estimator C)}
The following two prompts are passed to Claude Haiku 4.5 for each
candidate drawer, exactly as they appear in
\texttt{pipeline/llm\_surprise.py} in the shipped source. The 20 most
recent same-wing priors are concatenated in chronological order (each
prefixed with \texttt{[Entry N]}); the candidate drawer text is
substituted verbatim into \texttt{[Target]}. Each drawer is
normalized (fenced code blocks stripped, truncated to 2000 tokens
via the bge-m3 tokenizer) before entering either prompt slot.

\paragraph{System prompt.}
\begin{quote}
\ttfamily\small
You are a retrieval-quality rater. Respond with valid JSON only, no
prose, no markdown fences.
\end{quote}

\paragraph{User prompt.}
\begin{quote}
\ttfamily\small
Given these 20 prior memory entries:\\[0.4em]
[Entry 1]\\
\ldots\\[0.4em]
[Entry 20]\\
\ldots\\[0.4em]
Rate on a 1-10 scale how predictable the following entry is:\\[0.4em]
[Target]\\
\ldots\\[0.4em]
10 = entirely derivable from priors, 1 = entirely novel.\\
Return JSON: \{"score": int, "reasoning": short str\}.
\end{quote}

The surprise value is the inversion $C(d) = 10 - \mathrm{score}$
so higher $C$ means less predictable. The model's short prose
\texttt{reasoning} field is spot-checked in the audit log but does not
enter the correlations.

\paragraph{Cost per call and invocation.}
Claude Haiku 4.5 is called via the local \texttt{claude} CLI in
headless mode with the flags
\texttt{-p --output-format json --model claude-haiku-4-5\
--disable-slash-commands --no-session-persistence\
--strict-mcp-config --mcp-config /path/to/empty.json}. The empty MCP
config is required because default \texttt{claude} spawns user-config
MCP servers as short-lived Node subprocesses per invocation
(\char`\~ 130\,MB $\times$ 4 servers), which inflates the parent's
cgroup memory to the point of triggering \texttt{systemd-oomd} on
consumer hardware even though the Python parent's steady-state RSS is
$\sim$1.7\,GB. The final run cost \$0.031 $\pm$ 0.003 per drawer at
prevailing pricing, and reached the \$15 sample budget at $n = 787$
completed calls, of which $n_A = 792$ appear in the $\rho(A,C)$
correlation once resumed cached partials from earlier attempts are
merged. Six per-drawer 120\,s timeouts were skipped by the resumable
batch driver without aborting the run.
